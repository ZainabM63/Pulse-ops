DEMO LOGIN:          sarah@acme.com / password

--------------------------------------------------------------------------------
1. ARCHITECTURE
--------------------------------------------------------------------------------
Monorepo layout:
  - Laravel API backend (routes/api.php, all endpoints under /api/v1)
  - Decoupled Next.js SPA in frontend/ (App Router, client-side only, no SSR)
  - No Blade UI (only stock welcome page); UI is 100% Next.js
  - Broadcast events queued via database queue driver
  - Multi-tenancy via CompanyScope global scope (WHERE company_id = auth user)
  - api/index.php = Vercel serverless entry (tmp storage, auto-migrate on
    cold start via AppServiceProvider)

--------------------------------------------------------------------------------
2. FEATURES
--------------------------------------------------------------------------------

A) AUTHENTICATION (Sanctum bearer tokens)
   - POST /api/v1/register, /login, /logout, GET /api/v1/user
   - No password reset / email verification endpoints
   - Roles exist (admin/manager/member) but are NOT enforced server-side

B) INCIDENT MANAGEMENT
   - Full CRUD: GET/POST/PUT/PATCH/DELETE /api/v1/incidents
   - Filters: severity, status, assignee_id, unassigned; paginated
   - Severities: critical / major / minor / info
   - Statuses: investigating -> identified -> monitoring -> resolved -> postmortem
   - Auto-logs activities (declared, status change, severity change, assignment)
   - Auto-notifies involved users (reporter, assignee, team members)
   - blast_radius field, resolved_at auto-set, service linking (pivot)
   - Activity feed endpoint with after_id cursor polling (getChat)
   - Inline comments on update

C) INCIDENT WAR ROOM (real-time collaboration)
   - Chat via POST /incidents/{id}/chat -> IncidentActivity rows
   - Websocket broadcast: ChatMessageBroadcast on company.{id} channel
   - Slash commands (frontend): /ack, /escalate, /status, /help, /attach-log
   - Voice notes: MediaRecorder -> base64 in activity metadata -> VoiceNotePlayer
   - Voice announcer: SpeechSynthesis alerts for critical events
   - Elapsed timer, responder count, escalation timer
   - Root Cause Hypotheses panel: full CRUD on /incidents/{id}/hypotheses
     (title, confidence 0-100, status investigating/hypothesis/ruled_out/
      confirmed, evidence JSON, owner)

D) AI REMEDIATION AGENT (headline feature, Google Gemini)
   - Endpoints (throttled 30 req/min): /api/v1/agent/health, /agent/runs
     (index/store/show), /agent/runs/{run}/chat, /execute, /cancel
   - AgentBrain: Gemini function-calling (model gemini-3.6-flash), system
     prompt for SRE diagnosis -> remediate -> notify -> resolve
   - MockAgentBrain: deterministic keyword fallback when no API key
   - Multi-round loop (max 5 rounds): observe results, re-decide, dedupe,
     stop when no progress (sequential mode); autonomous mode auto-executes
   - 9 tool actions:
       restart_service       (real: sets service operational)
       scale_resources       (simulated)
       rollback_deployment   (simulated)
       send_notification     (real: Slack/Teams webhooks if configured)
       run_diagnostics       (real: reads company services, status breakdown)
       create_followup       (real: creates linked incident)
       generate_postmortem   (real: Markdown report)
       resolve_incident      (real: resolves + notifies + broadcasts)
       update_service_status (real: fuzzy name match, updates status)
   - AgentRun + AgentAction persistence, ownership authorization (403 if
     not owner), chat history per run, metadata.summary
   - Rich incident context: services, team, last 8 activities, 5 hypotheses,
     8 telemetry entries

E) SERVICES / TELEMETRY
   - Service CRUD with status (operational/degraded/partial_outage/
     major_outage), severity_level, auto-slug
   - SLO metrics: uptime, latency_ms, error_rate, slo_budget, tier
   - Circuit breaker: PATCH /services/{id}/circuit-breaker (closed/open/
     half_open)
   - TelemetryLog: GET/POST /api/v1/telemetry, filters by incident/level,
     levels info/warn/error/cmd, seeds 7 demo rows when empty

F) TEAMS / ON-CALL
   - Team CRUD (auto-slug), bulk user assignment (company-scoped)
   - GET /teams/users for pickers
   - Frontend: TeamCard (on-call, escalation, fatigue), HandoffModal shift
     handover

G) DASHBOARD & ACTIVITY LOG
   - GET /api/v1/dashboard: active incidents, critical/major counts,
     by_status breakdown, degraded vs total services (company-scoped)
   - GET /api/v1/activity-log: global feed with level classification,
     formatted "INC-0001 | Type | body" terminal messages

H) NOTIFICATIONS
   - GET /api/v1/notifications (paginated + unread_count)
   - POST /api/v1/notifications/read (ids or all, own only)
   - UserNotification rows + NotificationBroadcast on notifications.{userId}
   - Frontend: bell with 15s polling + Echo listener, browser Notification
     API, speech synthesis

I) REAL-TIME BROADCASTING (3 events, all ShouldBroadcast)
   - ChatMessageBroadcast     -> .chat.message     on company.{id}
   - IncidentUpdated          -> .incident.updated  on company.{id}
   - NotificationBroadcast    -> .notification.created on notifications.{userId}
   - Channels: App.Models.User.{id}, company.{id}, notifications.{userId}
     (routes/channels.php; broadcast auth uses auth:sanctum)
